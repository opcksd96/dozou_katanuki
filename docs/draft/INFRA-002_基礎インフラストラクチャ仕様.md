## 1. 外部サービス・ツール一覧

| サービス名 | 役割 | 技術スタック | 利用目的 | 連携方法 |
|------------|------|-------------|----------|-----------|
| **SNS (X/Twitter)** | ツイートの取得・投稿・検索 | X API v2, Twitter Client | ユーザーアカウント情報、投稿履歴の取得 | Axios HTTPクライアント経由 |
| **Wayback Machine** | オンラインアーカイブ（画像・動画の保存・復元） | Wayback Machine API | 過去のメディアコンテンツの永続保存 | Axios HTTPクライアント経由 |
| **Stashapp** | メディア管理（保存・削除・バージョン管理） | Stash API | メディアファイルのライフサイクル管理 | Axios HTTPクライアント経由 |
| **SQLite3** | 主データベース（永続化層） | SQLite3 + GORM ORM | ユーザー情報、投稿、メディアメタデータの保存 | GORM ORM 経由 |
| **Mortix (ARIA2クライアント)** | クラウドストレージ連携 | ARIA2 API | 外部メディアのバックアップ・転送 | Axios HTTPクライアント経由 |
| **JD2 (Downloader)** | ファイルダウンロード・転送 | JD2 Downloader | 大容量メディアファイルの効率的な取得 | Axios HTTPクライアント経由 |
| **Thunder (Thunderクライアント)** | リアルタイム通知・プッシュ | Thunder Protocol | リアルタイムの通知配信 | Axios HTTPクライアント経由 |

## 2. 各サービスの詳細仕様

### 2.1 SNS (X/Twitter)

| 項目 | 詳細 |
|------|------|
| **APIエンドポイント** | `GET /2/users/{id}/tweets`, `POST /2/tweets`, `GET /2/tweets/search` |
| **認証** | Bearer Token (OAuth 2.0) |
| **レート制限** | 1,500リクエスト/時間（標準） |
| **利用範囲** | ユーザーアカウント情報、投稿履歴、トレンド |
| **注意点** | 非同期処理での実装推奨（APIレスポンスの遅延対応） |

### 2.2 Wayback Machine

| 項目 | 詳細 |
|------|------|
| **APIエンドポイント** | `GET /web/archives/{identifier}` |
| **認証** | 認証不要（公開API） |
| **利用範囲** | 過去のメディアコンテンツの取得・ダウンロード |
| **注意点** | 検索機能は制限あり。特定のURLの取得が主目的 |

### 2.3 Stashapp

| 項目 | 詳細 |
|------|------|
| **APIエンドポイント** | `POST /stashes`, `GET /stashes/{id}`, `PUT /stashes/{id}` |
| **認証** | APIキー（環境変数 `STASH_API_KEY`） |
| **利用範囲** | メディアファイルの保存・削除・バージョン管理 |
| **注意点** | ファイルサイズ制限あり。大容量ファイルはJD2経由で転送推奨 |

### 2.4 SQLite3 (リレーショナルデータベース)

| 項目 | 詳細 |
|------|------|
| **データベースファイル** | `chronоarchive.db`（メインDB）、`archive.db`（アーカイブDB） |
| **GORM ORM** | `go-sqlite3` + `gorm.io/gorm` |
| **テーブル構成** | `accounts`, `tweets`, `media`, `stashes`, `audit_log` |
| **永続化方式** | MVVMの観点からは「ストレージ層」として、モデルデータの永続化を担当 |
| **注意点** | WAL（Write-Ahead Logging）モードを使用。トランザクション境界が重要 |

### 2.5 Mortix (ARIA2クライアント)

| 項目 | 詳細 |
|------|------|
| **APIエンドポイント** | `GET /v1/media/{id}`, `POST /v1/media` |
| **認証** | APIキーまたはOAuth |
| **利用範囲** | 外部メディアのバックアップ・転送 |
| **注意点** | 帯域幅制限あり。非同期処理推奨 |

### 2.6 JD2 (Downloader)

| 項目 | 詳細 |
|------|------|
| **APIエンドポイント** | `POST /download`, `GET /download/{id}` |
| **認証** | APIキー |
| **利用範囲** | 大容量メディアファイルの高速ダウンロード |
| **注意点** | 並列ダウンロードの制御が必要 |

### 2.7 Thunder (Thunderクライアント)

| 項目 | 詳細 |
|------|------|
| **APIエンドポイント** | `POST /thunder/events` |
| **認証** | APIキー |
| **利用範囲** | リアルタイム通知の受信・配信 |
| **注意点** | WebSocket接続が必要。接続維持の管理が必要 |

## 3. 連携方法と利用ガイド

### 3.1 データフロー設計

```
[外部サービス] → [HTTPクライアント] → [ビュー・モデル] → [ストレージ層]
                                  ↑
                                  └─ 直接オペレーション
```

### 3.2 各サービスの利用タイミング

| サービス | 利用タイミング | 注意点 |
|----------|----------------|--------|
| **SNS** | ユーザーアカウント情報取得時、投稿表示時 | 非同期処理で実装推奨 |
| **Wayback** | 過去のメディア取得時 | 検索機能は制限あり |
| **Stash** | メディア保存・削除時 | ファイル操作はJD2経由 |
| **SQLite3** | 全てのデータ操作（CRUD） | トランザクション管理必須 |
| **Mortix** | 外部メディアのバックアップ時 | 非同期処理推奨 |
| **JD2** | 大容量メディアダウンロード時 | 並列処理で効率化 |
| **Thunder** | リアルタイム通知受信時 | WebSocket接続の維持管理 |

### 3.3 利用時の注意点

1. **レート制限の管理**  
   - SNS・Stash・JD2は各サービスのレート制限を尊重  
   - 非同期処理（Promiseチェーンやバックグラウンドジョブ）で処理

2. **エラー処理**  
   - 各API呼び出しにはタイムアウトとリトライロジックを実装  
   - 失敗時はローカルキャッシュから代替データを提供

3. **セキュリティ**  
   - 全てのAPI通信はHTTPSを使用  
   - APIキーは環境変数（`.env`）に管理  
   - 認証トークンは短寿命（JWT）で発行

4. **監視・ログ**  
   - 各外部API呼び出しにログ記録（エラー含む）  
   - 遅延・失敗率のモニタリング

## 4. 利用時のベストプラクティス

| 項目 | ガイドライン |
|------|-------------|
| **非同期処理** | 外部API呼び出しは非同期で実装。UIは即座に返却。 |
| **トランザクション** | SQLite3ではトランザクションを使用。コミット後はキャッシュを更新。 |
| **キャッシュ戦略** | Redis（またはメモリキャッシュ）で頻繁にアクセスされるデータをキャッシュ。TTLは5分程度。 |
| **エラーハンドリング** | 外部APIが応答しない場合、ローカルデータで代替表示を提供。 |
| **スケーリング** | 読み取り負荷が高い場合は読み取りレプリカを検討。 |

---

## 5. トラブルシューティング

| 問題 | 原因 | 解決策 |
|------|------|--------|
| APIレスポンスが遅い | レート制限に達している | 非同期処理に分散、またはバックグラウンドジョブに移行 |
| データ不整合 | モデル・ビュー間の同期不整合 | トランザクション境界を明確にし、コミット後のキャッシュ更新を徹底 |
| 接続エラー | ネットワーク不安定 | 再試行ロジックを実装、タイムアウト設定を適切に設定 |

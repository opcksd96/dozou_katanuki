## 詳細内容

### 1. 永続化アーキテクチャの設計原則

#### 1.1 基本方針
- **データ永続化の原則**: 本プロジェクトでは、ユーザーリクエストによる**物理的削除は一切実行されない**。すべてのデータは論理フラグ（`status='archived'`）による非表示化のみ実行され、データはDB内に永久保持される。
- **ストレージ戦略**: DB永続化と外部ストレージ（Stashapp GraphQL）を組み合わせたハイブリッドアーキテクチャ
- **スケーラビリティ**: データ増加に応じた階層ストレージ方式（Hot/Warm/Cold）を採用
- **セキュリティ優先**: 機密情報は環境変数管理、アクセス制限は最小特権原则に準拠

### 2. 永続化ストラテジ

#### 2.1 データモデリング（テーブルスキーマ）
- **accounts テーブル**: ユーザー情報管理
- **tweets テーブル**: ツイート情報管理（`status` フィールドで「active」「archived」の2状態）
- **media テーブル**: メディア情報管理（`processing_state` フィールドで「queued」「completed」「failed」「archived」）

#### 2.2 永続化戦略
- **データ削除禁止**: トリガー・スキーマ制約で物理削除を排除
- **論理削除フラグ**: `status` や `processing_state` で管理
- **アーカイブシステム**: Stashapp経由での外部ストレージ連携を永続化基盤とする

#### 2.2 永続化ストラテジ
- **無制限保持**: すべてのデータは削除スケジュールなしで永久保存
- **インデックス維持**: 既存インデックスは継続使用可能
- **アーカイブ階層**: 
  - `hot/`（直近30日）: NVMe SSD保持
  - `warm/`（30~365日）: HDD保持  
  - `cold/`（365日以上）: AWS S3 Glacierに自動移行

#### 6. 永続化ストラテジ詳細
- **データ階層管理**:  
  ```mermaid
  graph TD
    A[新規取得データ] --> B[Hot Storage (NVMe)]
    B --> C[Warm Storage (HDD)]
    C --> D[Cold Storage (S3 Glacier)]
    D --> E[Archive (Wayback)]
  ```
- **ファイル命名規則**: `media_YYYYMMDD_{tweet_id}_{seq}.ext` 形式で命名
- **アーカイブ移行**: 30日経過データをS3 Glacierへ移行（自動化 scheduled job）

#### 7. 常時可用性戦略
- **可用性RPO**: 5分以内（テキストデータ） - RTO: 1時間以内
- **永続性保証**: S3 Glacierの不変性を活用した「書き込み不可」ストレージ構成

### 3. 認可モデル

#### 3.1 アクセス制御モデル
- **ROLE_BASED_ACCESS**: 
  - `ROLE_USER`: 読み取り専用アクセス
  - `ROLE_ADMIN`: 全データ閲覧 + 論理フラグ変更権
- **ポリシー強制**:  
  ```sql
  -- トリガーで物理削除を禁止
  CREATE TRIGGER prevent_physical_delete 
  BEFORE DELETE ON tweets 
  FOR EACH ROW 
  BEGIN 
      SELECT RAISE_APPLICATION_ERROR(-1, '物理削除は禁止');
  END;
  ```

### 4. 監柄と監査

#### 8.1 監査ログ強化
- **改ざん検知**: 重要テーブルにハッシュチェーン（SHA3-384）を導入
- **アクセスログ**: 全データアクセスを記録（SELECT含む）
- **月次監査**: データ整合性チェックを自動実行

#### 8.2 永続化ストラテジ具体化
1. **データ階層の具体化**:
   - `hot/` は NVMe SSD直下に配置し、 dbファイルを直接配置
   - `warm/` は定期スケジューラによりS3に移行
   - `cold/` はS3 Glacierに完全アーカイブ

2. **データ管理API**:
   - `/archive` エンドポイントは物理削除を受け付けない
   - `restore` エンドポイントは `processing_state='archived'` から復元

### 9. 永続化ポリシーの明示

> **重要**: 本プロジェクトにおける「削除」操作は、**データの永久保存を前提とした** 論理的ステータス変更のみを許可します  
> - `status='active'`：「通常表示可能」  
> - `status='archived'`：「非表示だがDB内に永久保持」  
> - `status='failed'`：「処理失敗だがデータは保持」
